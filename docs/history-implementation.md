# История просмотров — рабочий раздел курсовой

Статус: код подготовлен для feature/theme-switching; сборка и испытания ещё не выполнены. main не изменяется.

## Требования и данные

История предназначена для вошедшего покупателя; гостевые и служебные просмотры не записываются. Таблица public.product_view_history уже создана миграцией add_product_view_history. Владелец — UUID Supabase Auth, товар — bigint из products. Составной первичный ключ исключает повторение пары. Триггер задаёт время на сервере, индексы поддерживают сортировку. RLS ограничивает операции собственным UUID; фильтр в запросе не заменяет RLS.

## Реализация

SupabaseAuth сохраняет access token и UUID в памяти через HistoryClient при успешном входе. Токен не записывается в файл и не выводится в журнал. Возврат на экран входа очищает его. Запросы только новой истории используют пользовательский Bearer; старый SupabaseClient не меняется. Автоматического refresh token нет: истёкшая сессия требует повторного входа. Каждый фоновый запрос привязан к снимку идентичности; результаты старой сессии не выводятся после её смены.

SceneManager записывает просмотр после открытия карточки. HistoryFeature добавляет раздел истории в профиль перед личными данными и открывает модальное окно. Показаны последние 50 уникальных товаров, новые первыми. Повторное открытие выполняет upsert и обновляет время. Очистка удаляет всю собственную историю, а не только показанные 50 записей. Удалённые товары удаляются из истории по внешнему ключу; скрытые нельзя открыть через историю.

Сетевые операции новой функции выполняются последовательно в отдельном daemon-потоке с ограниченной очередью; обновление интерфейса выполняется через Platform.runLater. Последовательная очередь сохраняет порядок записи просмотра и последующего чтения/очистки. Встроенные запросы существующего ProductDetailController остаются вне этой доработки.

## План испытаний — НЕ ВЫПОЛНЕН

H-01: открыть два товара — оба в истории, последний первым.
H-02: повторно открыть первый — одна запись с новым временем, наверху.
H-03: выйти и войти тем же аккаунтом — история сохранена на сервере.
H-04: войти вторым аккаунтом — история первого не видна; прямые API-запросы к чужим строкам также запрещены.
H-05: очистить — удаляется только собственная история, включая записи за пределом списка 50.
H-06: гость и менеджер — просмотры не записываются.
H-07: открыть товар из истории — актуальная карточка и обновлённое время.
H-08: выключить сеть/дождаться истечения JWT — ошибка без зависания нового интерфейса.
H-09: сменить пользователя при фоновой операции — чужие результаты не появляются.
H-10: светлая и тёмная тема окна истории — читаемые элементы.

Результаты запуска, проверки RLS двумя аккаунтами и скриншоты пока отсутствуют. У старых таблиц RLS отключён; эта доработка не исправляет их общую модель доступа. Тема ранее проверена пользователем вручную; это не автоматический прогон тестов.
