# Контроль низких остатков — рабочий материал курсовой

Статус: миграция применена; Java-код подготовлен, сборка и испытания не выполнены. main не меняется.

products.low_stock_threshold — целое неотрицательное значение, начальное 5. Представление low_stock_products возвращает нескрытые товары с известным остатком не выше порога; ноль выделяется отдельно, NULL не подменяется нулём. security_invoker учитывает права исходной таблицы. SELECT представления предоставлен authenticated, не anon.

В панели менеджера предусмотрены сводка нулевых, низких и неизвестных остатков, ручное обновление и проверка раз в 60 секунд. Проверка прекращается при смене сцены. Это уведомления внутри открытого приложения, не фоновые уведомления ОС. После редактирования товара данные актуализируются кнопкой обновления или периодической проверкой.

Окно «Уведомления и пороги» имеет фильтр проблемных позиций и режим всех товаров для настройки порогов, поиск и проверку целочисленного ввода. Сохранение PATCH меняет только low_stock_threshold и проверяет ответ сервера. Остатки и цены не перезаписываются. Уведомления вычисляются заново, отдельные дублирующиеся записи не создаются. Чтение выполняется страницами по 200 с курсором ID, поэтому список не ограничен первой страницей API. Два чтения представления и товаров не являются общей транзакционной фотографией; следующий опрос обновляет возможные расхождения.

Используется JWT вошедшего пользователя через внутренний метод авторизации HistoryClient, без выдачи токена интерфейсу или записи на диск. Проверка роли менеджера в Java не является серверной защитой: RLS исходных старых таблиц отключён, и пользовательские роли пока не защищены полноценной серверной моделью. Эта доработка не должна описываться как готовая производственная система разграничения доступа.

В основной менеджерской таблице подсветка остатка обновляется по индивидуальному порогу; неизвестное значение выводится отдельно. Новые операции работают в daemon-потоке с ограниченной очередью; интерфейс обновляется через Platform.runLater. При ошибке сохранения/последующего чтения интерфейс предупреждает о неопределённом результате и предлагает обновить данные, а не заявляет ложный успех. Автоматического refresh JWT нет.

План испытаний (не выполнен): остатки 0, 5, 6 при пороге 5; порог 0; индивидуальный порог выше остатка; отрицательное, дробное и слишком большое значение; NULL остаток; скрытый товар; сохранение порога нормального товара; периодическое обновление; остановка таймера после выхода; обе темы; ошибки сети и истёкший JWT; отсутствие изменений цены/остатка при сохранении порога. SQL в репозитории отражает уже применённую миграцию, повторно выполнять его не требуется.
