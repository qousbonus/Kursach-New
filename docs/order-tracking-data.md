# Отслеживание заказов: слой данных

Статус: миграция add_order_tracking_history применена; клиентский слой подготовлен, сборка и испытания не выполнены. Окно хронологии и новые элементы управления менеджера в этот коммит не входят.

Новые created_at/updated_at приходят с сервера и переводятся в часовой пояс устройства. Для старых заказов дата создания остаётся NULL. Журнал имеет события created, status_changed и snapshot. Снимок при внедрении не является датой прошлого изменения. Триггер пишет событие в транзакции изменения заказа; повторный статус не создаёт событие.

OrderTrackingClient использует JWT текущей сессии, получает сведения и все страницы журнала, сортирует события по времени и ID. Чужая сессия не должна получать результаты отложенного запроса. Покупатель в клиентском коде ограничен чтением своего заказа и подтверждением shipped → delivered; сотрудник выбирает допустимый код из шести статусов. Проверка обновления включает HTTP-ответ, количество возвращённых строк, ID и статус. PATCH содержит условия по текущему статусу и точному updated_at для обнаружения конкурентного изменения. Для будущего интерфейса предусмотрен changeExpected с проверкой статуса выбранной строки.

OrderRepository теперь читает даты и делегирует смену статуса этому клиенту. Создание заказа сохраняет начальный confirmed и существующий способ создания позиций. Транзакционность всего оформления не исправлена: ошибка отдельной позиции всё ещё требует отдельной доработки. Первичный автор события при старом анонимном пути создания может быть NULL. Строгая серверная машина переходов и автоматический возврат остатков при отмене не добавлялись.

RLS нового журнала разрешает чтение по текущим профилям и email JWT, а записи выполняются триггером. Старые users/orders доступны без полноценных RLS-политик, их поля изменяемы: это ограничивает надёжность определения владельца и сотрудника. Прямое удаление родительского заказа каскадно удаляет его журнал. Функция не является защищённым от подмены производственным аудитом. Эти ограничения нельзя скрывать в документации.

Проверки пока не выполнены: новый и старый заказ; повторный статус; смена с JWT; отказ API; конкурентный PATCH; чтение двумя аккаунтами; сортировка более 200 событий; часовой пояс. Проверки интерфейса добавятся при подключении хронологии. main не изменяется.
