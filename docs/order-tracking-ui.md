# Интерфейс отслеживания заказов

Статус: подготовлен кандидат кода; сборка и испытания не выполнены. Используется ранее записанный OrderTrackingClient. Элементы менеджера подключаются слушателем сцены в Main после применения CSS и layout; остальные установщики SceneManager не меняются. main и схема Supabase в этом коммите не меняются.

В карточке покупателя предусмотрена кнопка «Отследить заказ». Окно показывает текущий статус, даты создания и обновления в часовом поясе устройства, журнал переходов и отдельную подпись для snapshot. Неизвестная дата создания старого заказа не заменяется датой внедрения. История обновляется вручную или каждые 15 секунд до закрытия окна. Отсутствующие или недоступные события не выдаются за доказанное отсутствие истории.

Менеджеру добавлены шесть статусов с русскими названиями, фильтр по каждому статусу, кнопки просмотра истории и фонового обновления списка, колонка даты создания. Смена статуса и подтверждение получения покупателем выполняются в фоне, с подтверждением и проверкой результата сервера. Ошибка не выдаётся за успех. Повторный статус не создаёт новое событие; интерфейс сообщает текущее подтверждённое состояние. Условный PATCH обнаруживает изменение статуса после выбора строки и конкурентное изменение во время запроса.

Серверный order_status_history является основным журналом. Дополнительно запись system_logs отправляется асинхронно по принципу best effort: её недоступность не отменяет подтверждённое изменение заказа. Контекст пользователя фиксируется до отправки; ответы другой сессии не показываются. Чтение состояния и журнала — отдельные запросы, поэтому это не неизменяемый общий снимок при конкурентном обновлении. Следующий опрос актуализирует отображение.

Строгая серверная машина допустимых переходов не добавлена: сотрудник выбирает один из шести существующих кодов. Автоматического возврата остатков при отмене нет; подтверждение отмены предупреждает об этом. Проблемы прав старых таблиц и нетранзакционного оформления заказа, описанные в order-tracking-data.md, сохраняются. Legacy-загрузка заказов при первичном открытии экрана не переработана; новые сетевые операции работают в отдельных потоках.

План проверки (не выполнен): кнопка покупателя; новый заказ с created; старый заказ со snapshot; все статусы и фильтры менеджера; подтверждение shipped → delivered; повторный статус; конфликт обновления; ошибки API; два аккаунта и доступ к чужой истории; часовые пояса; обе темы; прекращение опроса при закрытии; регрессия каталога, истории и контроля остатков. До выполнения проверок функция не считается завершённой.
